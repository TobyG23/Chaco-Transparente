# Contribuir

Este repositorio contiene un núcleo **offline** de ingestión para dos vistas provinciales de 2022. La Misión 004 añade un frontend editorial en `packages/web`; la Misión 004.2 autoriza únicamente un commit local revisado, no push ni despliegue. No hay autorización para publicar importes ni incorporar nuevas fuentes o datos oficiales a Git.

1. Proponer cambios pequeños y acompañarlos de pruebas con datos sintéticos. Conservar los códigos y celdas originales, trazabilidad por línea y aritmética decimal exacta.
2. Usar Bun 1.4.3 y el lockfile vigente. Instalar con `bun install --frozen-lockfile --ignore-scripts`; revisar cualquier cambio de dependencias y su integridad antes de ejecutar binarios nuevos. Turbo 2.9.14 ejecuta typecheck, pero avisa que no interpreta el lockfile Bun v2; ver `MISSION-003-FINAL.md` antes de depender de su grafo o caché.
3. Ejecutar `bun run test`, typechecks directos de cada workspace y `bun run lint`. Para el frontend, ejecutar `NEXT_TELEMETRY_DISABLED=1 bun run web:build` (en PowerShell: `$env:NEXT_TELEMETRY_DISABLED='1'; bun run web:build`) y revisar el árbol `packages/web/out/` local antes de considerar cualquier entrega: rutas, enlaces, ausencia de archivos privados y datos. `noindex` no controla el acceso. La integración opcional requiere rutas externas verificadas en `CHACO_FINALIDAD_CSV` y `CHACO_OBJETO_CSV`; un test omitido no equivale a una integración aprobada. La CLI escribe sólo bajo `data/`, que está ignorado por Git.
4. Revisar **cada archivo** antes de proponerlo: nunca incluir CSV oficiales, derivados presupuestarios, secretos, `.env`, logs, caches o carpetas temporales. `.gitignore` no impide `git add -f`.
5. No afirmar semántica normativa para `Q_*`, moneda/unidad, licencia de los datos ni permiso de publicación mientras permanezcan pendientes. No copiar código o activos de proyectos de referencia sin verificar sus derechos y atribución.

El código original del proyecto se ofrece bajo [MIT](LICENSE); los textos y el diseño originales, bajo [CC BY 4.0](LICENSE-CONTENT.txt). Quien contribuya debe poder conceder derechos compatibles sobre su aporte y señalar material ajeno y su atribución; estas licencias no cubren recursos oficiales ni materiales de terceros. Para asuntos de seguridad, consultar `SECURITY.md`.
