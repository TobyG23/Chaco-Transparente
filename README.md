# Chaco Transparente — núcleo offline y portal editorial local

`packages/web` comenzó como portal editorial de seis páginas sobre fuentes, metodología y estado. `/datos` incluye un **explorador interactivo exclusivamente sintético**: sus filas y cantidades ficticias no son registros oficiales y llevan el aviso exacto «Datos sintéticos de demostración · no son registros oficiales». Este texto no certifica un despliegue ni autoriza publicar cifras reales. Ni el explorador ni el export deben leer, copiar o publicar CSV originales, filas, JSON derivados o importes oficiales. Para construir y verificar localmente el export estático, incluidos avisos de licencias, usar `bun run web:verify`; para desarrollo local: `bun run web:dev`. Ver `ARCHITECTURE-WEB.md`, `DESIGN-SYSTEM.md`, `CONTENT-STATUS.md` y `QA-WEB.md`. La validación histórica del núcleo de Misión 003 se conserva más abajo.

Prototipo local para **dos** vistas de la ejecución presupuestaria provincial acumulada enero–diciembre 2022. No es una serie mensual ni un presupuesto municipal completo. Las vistas son desgloses distintos de la misma ejecución: **no sumarlas entre sí**. Fuente: [Ejecución Presupuestaria, Datos Abiertos Chaco](https://datosabiertos.chaco.gob.ar/dataset/ejecucionpresupuesto), organismo CKAN «MINISTERIO DE PLANIFICACION, ECONOMIA E INFRAESTRUCTURA». Los recursos están etiquetados CC BY 4.0 por el portal; su formulación legal/atribución y permisos de republicación requieren revisión.

Los códigos `Q_*` se conservan tal como aparecen; la moneda, unidad, definición de `Q_VAR` y definiciones normativas de las etapas **no están confirmadas**. En particular `Q_PAG` no se presenta como desembolso efectivamente pagado. `publicationAllowed` e `isPublished` son siempre `false` **para datos reales** en el núcleo, aunque la validación técnica local termine sin errores; incorporar demostraciones sintéticas no cambia estos indicadores ni relaja ese bloqueo. La CLI de ingestión no utiliza red, API, servidor ni ruta de publicación; la herramienta de investigación local también opera sin servidor y sólo se inicia explícitamente. El frontend separado puede iniciar un servidor de desarrollo local o generar HTML estático, sin autorización de despliegue.

## Explorador oficial local (terminal, sin servidor)

Desde la raíz confiable del repositorio, con Bun 1.4.3 y dependencias instaladas, ejecutar **explícitamente**:

```text
bun run research -- "C:\ruta\absoluta\finalidad-original.csv" "C:\ruta\absoluta\objeto-original.csv"
```

Las rutas deben ser absolutas y apuntar a las dos copias originales verificadas; un hash/tamaño incorrecto impide abrir la sesión. Este comando no sirve ninguna página ni abre puertos: la interfaz aparece en la terminal hasta escribir `quit`. Escribir `help` para ver los comandos: `view finalidad|objeto`, `search texto`, `filter COLUMNA valor exacto` (sin valor elimina ese filtro), `sort COLUMNA asc|desc`, `page N`, `inspect LÍNEA`, `dictionary`, `quality`, `evidence` y `clear`. Se muestran 25 filas por página; `inspect` utiliza el número de línea física del CSV. Evitar copiar/transmitir capturas y salidas de esta terminal: contienen filas oficiales. No hay exportación de consultas a destinos arbitrarios; sólo puede generarse el expediente privado fijo descrito abajo. No introducir contraseñas ni tokens. Los dos CSV permanecen fuera de Git; no usar `bun run web:dev` ni `/datos` para consultarlos: `/datos` sigue siendo exclusivamente sintético.

Para investigar casos y entidades, ejecutar la misma CLI: `entities` enumera los 54 códigos; `entity 0024` selecciona una entidad (sin espacios iniciales del CSV), `entity clear` deselecciona. `view finalidad|objeto` cambia clasificación sin combinar sus importes; `filter Q_PARTIDA 115` y `filter Q_FTE 10` filtran objeto, mientras `filter CODFTE 10` filtra finalidad. En objeto, `anomaly negative|residual|zero-vig|none` selecciona respectivamente saldo registrado negativo, negativo con residual exacto no nulo, negativo con vigente cero/compromiso positivo, o todos; `cases` informa intersección y unión sin duplicar, `stats` muestra recuentos de la selección y `source` procedencia y documentación. `inspect LÍNEA` muestra celdas originales, SHA de origen y residual firmado incluso si la línea no está en la página actual, respetando la entidad elegida. `dossier` crea **una sola vez**, bajo `data/` ignorado por Git, un expediente HTML privado con los casos prioritarios y valores originales; rechaza sobrescribirlo. Ese archivo contiene importes y filas oficiales: no compartirlo, abrirlo por servidor, subirlo a Git/CI ni incorporarlo al export.

`review_required` indica que pasó el control técnico pero **no** que se haya certificado semántica, unidad, moneda, derechos, privacidad ni publicación. `rejected` identifica errores QA que exigen investigación; ambos mantienen `publicationAllowed=false` y filas `isPublished=false`. La ficha de `Q_VAR` es contradictoria entre vistas: la alerta heurística de QA no establece su fórmula. No sumar totales de las dos vistas. Ver la matriz por indicador en `PROVENANCE.md`.

## Ejecución

Requiere Bun y dependencias fijadas, obtenidos de fuentes aprobadas y verificadas. Instalar dependencias tras revisar manifiesto y scripts, preferentemente con `bun install --ignore-scripts`, y conservar el lockfile real; no ejecutar instaladores desde la carpeta de datos. Desde el directorio raíz del código:

```text
bun run ingest -- <ruta-absoluta-finalidad-original.csv> <ruta-absoluta-objeto-original.csv> [data/directorio-salida]
bun run test
bun run typecheck
bun run lint
```

Los dos argumentos de entrada son obligatorios; la salida sólo puede estar dentro de `data/` ignorado por Git. Si se indica un subdirectorio de salida nuevo, su padre inmediato ya debe existir y estar bajo control del operador (sin junctions/symlinks ni permisos de escritura de terceros). Los bytes deben corresponder exactamente a las copias auditadas: finalidad 87.111 bytes SHA-256 `5ecf7a89a9df8c8a4d4cc1b44464cf6cf4f46108634faedc4639c794679cdab7`; objeto 918.019 bytes SHA-256 `300bd7ce059bf22c94cbbe793326eac04153b93467841a75302828d21b43b5e0`. El hash se comprueba de nuevo cada vez, antes de parsear; es un control de identidad/integridad **local**, no validación de cifras ni permiso para difundirlas. Para activar la prueba de integración, proporcionar las rutas en `CHACO_FINALIDAD_CSV` y `CHACO_OBJETO_CSV`; sin ellas el test se omite. Los originales no forman parte de este proyecto.

La salida predeterminada es `data/` (ignorada por Git): versiones por hash, bytes sin modificar, JSON de filas y `quality.json`. El archivo conserva `sourceLine` físico 1-based y SHA-256 de los bytes de esa línea **sin CRLF**. Se rechazan campos CSV multilínea para mantener esa correspondencia. El CSV se decodifica como Windows-1252 compatible, no como codificación declarada oficialmente. Los importes normalizados son cadenas decimales exactas, nunca flotantes binarios. Los umbrales de QA se versionan y provienen de estas muestras; los saldos negativos y diferencias pequeñas se conservan, no se corrigen.

## Reproducción y estado de validación

El ZIP oficial de Bun v1.4.3 para Windows x64 se verificó contra el SHA-256 expuesto por GitHub y, tras autorización expresa, se extrajo al perfil de usuario. `bun --version` devolvió 1.4.3 y se generó `bun.lock` real con `bun install --ignore-scripts`. En Misión 003.2 se obtuvieron 9 tests (incluida integración real), typecheck, lint y dos ejecuciones idénticas de CLI. En Misión 003.3 se instaló Turbo 2.9.14 con scripts deshabilitados y se regeneró `bun.lock`; pasaron 14 tests (incluida integración), typecheck y lint, y dos ejecuciones CLI conservaron la misma versión local. Turbo advierte que no interpreta el lockfile Bun v2, aunque ejecuta las tareas; ver limitación en `MISSION-003-FINAL.md`. Los resultados y riesgos están en `MISSION-003-VALIDATION.md` y `MISSION-003-FINAL.md`. Para reproducirlos, hacer disponible el Bun verificado en el PATH de la sesión, asignar `CHACO_FINALIDAD_CSV` y `CHACO_OBJETO_CSV` a las copias externas verificadas y ejecutar los comandos anteriores. No interpretar un test omitido como integración aprobada.
